# DYEC 19.0.35 / DayOA 16.0.23 release ledger

## Objective

Publish an immutable DYEC patch whose global DayOA default, active command
catalog entries, and new command-catalog snapshot all pin the fully validated
DayOA `16.0.23` release. Preserve every historical catalog snapshot and the
normal production command shapes.

- Clean base: annotated DYEC `19.0.34`, peeled commit
  `7fd5370a1bb15cf556691cd034ea360514a40c31`.
- Candidate branch: `codex/dyec-19-0-35-dayoa-16-0-23` in the clean release
  worktree `/Users/jmajor/projects/lsmc/.codex-worktrees/dyec-19-0-34-release-run`.
- Candidate DYEC tag `19.0.35` was absent from origin at inventory time.
- DayOA `16.0.23` is an annotated origin tag peeling to
  `76ec851bb24ae78bf4e8d88c94d375bf297f1335`. It contains the unchanged
  DayOA `16.0.22` runtime that completed both HG002 validation capsules, plus
  their terminal validation and Slack evidence.
- The operator's ordinary DYEC checkout is not used or modified.
- Per operator direction, no pytest or generic git-test suite is run. Release
  validation uses direct catalog invariants and the public DYEC catalog CLI.

## Josh Durham release-lineage audit

- The relevant Josh Durham annotated tag is DYEC `19.0.23`, peeling to merge
  commit `e33cc9f6c4ba1cb4305980e21cf3d29a7ea74050`.
- `git merge-base --is-ancestor 19.0.23 19.0.34` returned zero, proving the
  current release base descends from that tag.
- `19.0.23` changed 21 IAM, cluster-create, renderer, baseline-capture,
  workflow, documentation, and test paths. None of those paths has any content
  diff between `19.0.23` and `19.0.34`; the audit command that intersected the
  `19.0.22..19.0.23` path set with `19.0.23..19.0.34` returned no paths.
- The Josh release did not touch the command catalog or
  `daylily_ec/repositories.py`. Therefore this candidate retains that release
  intact while changing only the new pin/snapshot/version surfaces and this
  ledger.
