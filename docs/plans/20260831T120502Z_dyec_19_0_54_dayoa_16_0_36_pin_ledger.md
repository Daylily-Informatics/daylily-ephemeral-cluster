# DYEC 19.0.54 / DayOA 16.0.36 pin ledger

## Objective

Create the narrow DYEC `19.0.54` source release candidate that pins the exact
annotated DayOA `16.0.36` release globally and for every production command,
push its release branch without merging to `main` or creating a DYEC git tag,
then bring the operator checkout forward and force-configure `clu-19052x` if
the exact-release contract can be satisfied.

## Boundaries

- Build only from exact annotated DYEC `19.0.53`, peeled commit
  `3f23ce6f8007d9dbbd03c38798076936882fd869`.
- Pin exact annotated DayOA `16.0.36`, tag object
  `32e66402c5b6f7be21bcedb468f6955aeecf2934`, peeled commit
  `319c253a14ebd4bb99c01f33ac967c9e2448f932`.
- Change only `CURRENT_DYEC_BUILD`, active catalog DayOA pins, a new immutable
  `19.0.54` snapshot, the packaged catalog mirror, and this ledger.
- Preserve every earlier numeric catalog snapshot byte-for-byte.
- Run no pytest or other test suite. Static source/readback evidence is allowed.
- Do not merge to `main`.
- Do not substitute a branch, commit SHA, version override, or inferred ref for
  the public headnode configure exact-release requirement.
- Preserve the operator checkout's untracked runbooks, ledgers, and artifacts.

## Gate 0 baseline

- Operator checkout: detached exact `19.0.53`; no tracked changes; pre-existing
  untracked `docs/etc/`, ledgers, and artifacts are outside release ownership.
- Isolated release worktree/branch:
  `codex/dyec-19-0-54-dayoa-16-0-36` from exact `19.0.53`.
- `19.0.54` is absent locally and from origin as both branch and tag at Gate 0.
- Active catalog has 33 commands plus one default pin at DayOA `16.0.35`, with
  11 production commands; immutable `19.0.53` has the same 33 commands and 11
  production commands.
- Source and packaged catalogs are byte-identical at baseline SHA-256
  `b315261339bbb4c5c4303e8db9661f049adbc2aeff47deb46663ce226d3b1db9`.
- Exact cluster configure authority:
  `/Users/jmajor/.config/daylily/state_clu-19052x_20260830223106.json`, profile
  `lsmc`, region `us-west-2`, cluster `clu-19052x`.
- `dyec headnode configure` calls `get_release_version()`, which rejects any
  non-exact semver-tagged executable, and requires the repository ref to equal
  that exact version. After this conflict was reported, the human explicitly
  superseded the no-tag boundary with: "just cut me a new dyec ver". The release
  therefore includes an annotated `19.0.54` tag so the requested local and
  headnode exact-release steps can run without a fallback.
